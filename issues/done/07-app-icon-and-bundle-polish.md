# App icon and bundle polish

**Type:** HITL

## What to build

Klokki currently bundles with Electron's default icon, so `pnpm build:mac`
produces something that looks like a sample project. This slice gives it its own
identity: an app icon compiled to `.icns` and wired into the electron-builder
config, and a look at whether the menubar glyph should match it.

This one needs a human: the artwork is a taste call, not a spec. Bring a
candidate or two, decide, then wire it in. The generated-from-code approach used
for the menubar template images is worth keeping if the chosen mark is simple
enough to draw — the repo carries no opaque binaries today, which is a property
worth not losing by accident.

## Acceptance criteria

- [x] An app icon exists at the sizes macOS wants and is compiled to `.icns`
- [x] `pnpm build:mac` produces a `.dmg` whose app shows the custom icon in
      Finder and in the Get Info panel
- [x] The menubar glyph and the app icon read as the same product
- [x] The icon source is either generated by a script or committed with a note
      on how it was produced — no unexplained binary
- [x] The bundle identifier stays `de.te-ce.klokki` and the app still launches as
      a menubar-only app with no Dock icon

## What was built

A notched clock on an Ink squircle, drawn by `pnpm icons` — the artwork was
chosen from rendered candidates rather than specified, which is what made this
HITL. `scripts/icon/` holds the geometry, the optical sizing curve, and PNG and
`.icns` encoders written out longhand so the format stays under test; nothing
binary is committed except the two menubar templates, which are loaded at
runtime and came out byte-identical to the ones they replace.

Verified on the real artifact: `iconutil` unpacks the generated `.icns` into all
ten expected slots, and the app inside `dist/Klokki-0.0.0-arm64.dmg` carries that
exact file (same SHA-256) with `CFBundleIconFile: icon.icns`,
`CFBundleIdentifier: de.te-ce.klokki`, and `LSUIElement: true`.

Two decisions are recorded in AGENTS.md, because both look like bugs to a future
reader: the app icon's stroke is optically sized per slot rather than downscaled
from one master, and the menubar glyph keeps a quarter past twelve where the app
icon shows ten past ten — at menubar weight two hands leaning the same way merge
into a single wedge, and no weight or hand length fixes it.
